## Day 7: MongoDB Atlas `$rankFusion` Hybrid RAG & Voyage `rerank-2.5` Service
- **Status:** `[x] Completed`
- **Completion Summary (2026-11-02):** Built `services/retrieval.service.ts`. The sanitized query is re-scanned with the shared `detectRawPiiLeakage` and rejected with `RetrievalRejectedError` (`ZERO_TRUST_VIOLATION`, categories only, before any Voyage or MongoDB call), then embedded with `voyage-context-3` (`input_type: query`). Pure builders emit the native `$rankFusion` stage with two named, weighted sub-pipelines: `vectorPipeline` (`$vectorSearch` on `embedding`, 250 ANN candidates, limit 25, optional `documentId $in` pre-filter) and `fullTextPipeline` (BM25 `$search` compound over `sanitizedContent` plus `sectionTitle` boosted 2x, plus an exact `in` clause on the `placeholderTokens` token field boosted 5x for any `[CATEGORY_HEX4]` token in the query, so `[MRN_3F90]` ranks first and never matches `[MRN_3F91]`; optional `documentId` filter). These are followed by `$limit: 25` and a `$project` that drops the 1024-d `embedding` and pulls `$meta: "scoreDetails"`. The top 25 fused candidates (section path plus content) go to `voyageService.rerank(query, docs, 5)`. The top 5 come back as `RetrievedChunk`s, each with `[CIT-01]`..`[CIT-05]` markers, `score` (rerank relevance clamped to [0,1], so each chunk satisfies the shared `CitationChunkSchema`) and `scoreDetails` (`fusion`: RRF score, fused rank, source, and per-pipeline `{rank, weight, rawScore}` or `null` when a pipeline missed the chunk; `rerank`: model, relevance, final rank). Each result also carries `candidateCount` and `embedMs`/`fusionMs`/`rerankMs`/`totalMs` timings for Day 8. **Compatibility fallback:** `$rankFusion` needs MongoDB 8.1+, but docker-compose ships `atlas-local:8.0`, so `fusionMode: "auto"` (the default) catches error 40324 (unrecognized stage), runs both sub-pipelines itself and applies the same `weight / (60 + rank)` RRF client-side. It remembers this for later queries. `"native"` and `"client"` force a path. Index names now live in `models/document-chunk.model.ts`. Built `scripts/setup-indexes.ts` (`pnpm --filter @aegis/api setup:indexes [--no-wait]`). It creates the collection if it is missing, ensures the B-tree indexes, and reconciles `document_chunks_vector` (vectorSearch: 1024-d cosine `embedding` plus `documentId` filter field) and `document_chunks_text` (search: `lucene.standard` on `sanitizedContent`/`sectionTitle`, `token` on `placeholderTokens`/`documentId`, `dynamic: false`). Missing indexes are created in one call; drifted ones are updated; matching ones are left alone, compared as a subset so Atlas-added defaults are not mistaken for drift. It then polls until both are queryable, failing on a `FAILED` build, a type clash or a timeout. 25 tests in `src/__tests__/retrieval.service.test.ts` run against an in-memory fake Atlas that executes the emitted `$rankFusion`/`$vectorSearch`/`$search`/`$limit`/`$project` stages over a 34-chunk clinical corpus embedded with the mock Voyage client. They cover the builder shapes, RRF maths and weights, `scoreDetails` parsing (rank 0 or a missing entry means not returned), 25-to-5 reranking with valid citation chunks and no embeddings returned, an exact placeholder identifier and an ICD-10 code ranked first via BM25, semantic-only matches surviving fusion, final order following the reranker, `documentIds` scoping, the fallback (results identical to native) and its caching, no fallback in native mode or on unrelated errors, the raw-PII query refused before any I/O, empty and oversized queries, and index create/idempotency/drift/wait/failure paths. Mutation checks: removing the exact-token clause, the PII guard, the fallback, or the use of the reranker's order each fails a test. `pnpm --filter @aegis/api test && pnpm turbo run typecheck` and `pnpm turbo run test` pass clean (131/131 tests across shared/web/api, 0 type errors). Not exercised against a live Atlas cluster in this environment (no Docker); run `docker compose up -d mongodb && pnpm --filter @aegis/api setup:indexes` first. The local 8.0 image takes the client-side fusion path.

## Day 8: Vercel AI SDK Streaming Controller & Citation Grounding Engine
- **Status:** `[x] Completed`
- **Completion Summary (2026-11-04):** Added `ai` 7 (Vercel AI SDK), `@ai-sdk/anthropic` 4 and `@ai-sdk/provider` 4 to `@aegis/api` (plus `ioredis-mock` for tests; zod raised to ^3.25.76 for the SDK's peer range). `services/prompt-builder.service.ts` builds a static, cacheable system prompt (`aegis-grounded-v1`) that requires `[CATEGORY_HEX4]` placeholders to be copied character for character, forbids guessing or inventing values, requires `[CIT-XX]` markers after every sourced sentence, and treats source text as data rather than instructions.
